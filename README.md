# repo-to-feishu-wiki

将 GitHub 或本地仓库中的 Markdown、VitePress、Quarto 等内容，可靠地转换并同步到飞书知识库。

这是一个面向 Codex/Agent 的工作流 Skill。它定义同步架构、内容转换规则、安全边界和验收标准，不是一个独立的同步 CLI，也不会脱离具体仓库直接执行批量写入。

## 能力概览

- 将仓库目录映射为有层级的飞书 Wiki 树。
- 支持一次性导入、持续单向镜像和接管已有知识库。
- 处理 frontmatter、目录首页、多语言内容和深层目录。
- 转换站内链接、本地图片、公式、Mermaid、VitePress/Quarto 专用语法。
- 通过稳定键和远端清单复用节点，支持重命名、移动、归档和断点恢复。
- 使用正文与资源联合哈希实现增量更新和无变化跳过。
- 覆盖本地测试、远端全量验收和 GitHub Actions 验证。
- 默认保护未知节点，优先归档而不是物理删除。

## 适用场景

当你希望完成以下任务时，可以使用本 Skill：

- 把项目文档一次性导入飞书知识库。
- 将 GitHub 文档分支持续镜像到飞书。
- 为 Markdown、VitePress 或 Quarto 文档建立飞书 Wiki。
- 修复重复节点、链接失效、图片不更新或同步中断等问题。
- 为已有同步器补充增量状态、CI 和远端验收能力。

本 Skill 默认实现“仓库为唯一真源”的单向同步。它不默认处理双向编辑合并；持续镜像时，飞书中的人工正文修改可能被后续同步覆盖。

## 安装

将本目录复制到 Codex 能识别的 Skills 目录：

```bash
cp -R repo-to-feishu-wiki ~/.codex/skills/
```

安装后，确保 `SKILL.md` 位于以下路径：

```text
~/.codex/skills/repo-to-feishu-wiki/SKILL.md
```

实际操作飞书或 GitHub 时，还需要当前环境提供对应能力：

- `lark-shared`：认证、身份、scope 和通用错误处理。
- `lark-wiki`：知识空间与 Wiki 节点操作。
- `lark-doc`：飞书文档正文读取与覆盖。
- `lark-drive`：标题、资源、权限与 token 检查。
- `github:github`：GitHub 仓库、Actions、Secrets 和 PR 操作，可选。

## 使用方式

在 Codex 中直接描述目标，并显式指定本 Skill。例如：

```text
使用 $repo-to-feishu-wiki，把当前仓库的 docs 目录一次性导入一个新的私有飞书知识空间。先输出只读计划，不要立即写入。
```

```text
使用 $repo-to-feishu-wiki，为当前仓库设计 GitHub 到飞书知识库的持续单向同步。删除页面时归档，保留重命名后的节点 token，并配置每日定时任务。
```

```text
使用 $repo-to-feishu-wiki，诊断现有同步器为什么在图片内容变化但路径不变时没有更新。只分析原因，暂不修改代码或远端内容。
```

开始前最好明确以下信息：

1. 同步模式：一次性快照、持续镜像或接管已有知识库。
2. 内容范围：仓库、分支、目录、文件类型和语言树。
3. 飞书目标：私有空间、根节点以及 user/bot 身份。
4. 删除策略：归档或显式物理删除。
5. 自动化方式：手动执行或 GitHub Actions 定时同步。
6. 验收范围：页面、层级、链接、图片、公式、Mermaid、权限和 CI。

## 工作流

典型执行流程如下：

1. 只读审计仓库内容、失效资源、站内链接和远端访问条件。
2. 选择一次性快照或持续镜像的最小架构。
3. 以规范化仓库相对路径建立稳定内容树。
4. 先创建或解析完整节点树，再转换正文、资源和内部链接。
5. 生成只读计划，经确认后串行写入飞书。
6. 保存检查点和版本化清单，处理更新、重命名与归档。
7. 执行本地测试、全量远端验收和真实 CI 验证。

持续同步的状态机、清单字段、重命名与恢复策略详见 [references/sync-design.md](references/sync-design.md)。完整测试矩阵和上线门槛详见 [references/verification.md](references/verification.md)。

## 默认安全策略

- 默认创建或使用私有知识空间。
- 默认先预览计划，再执行远端写入。
- 默认串行写入同一知识空间，减少限流和状态竞争。
- 默认将失效页面移动到归档区，不物理删除。
- 只操作清单明确拥有的节点，不按同名标题认领或删除内容。
- 发现未知子节点、清单损坏或 token 漂移时停止执行。
- 不在代码、状态、日志、报告或命令参数中保存 Secret 和访问令牌。
- QMD 默认按静态源解析，不执行代码单元。

## 完成标准

只有在以下证据齐全时，才应宣称同步完成：

- 本地转换测试和静态检查通过。
- 预期页面与远端节点一一对应，标题和父子层级正确。
- 正文、内部链接、图片、公式和 Mermaid 已在远端核对。
- 知识空间私有性、成员权限和外部分享设置正确。
- 无变化重跑为 no-op，正文或图片变更能触发预期更新。
- 重命名复用原节点，删除按策略归档或删除，中断后可安全续跑。
- 若启用 CI，真实 GitHub Actions Runner 已成功执行并生成报告。

如果任务只完成了方案设计、本地实现或抽样检查，应明确说明尚未完成真实远端全量验收。

## 维护建议

飞书与 GitHub 的命令参数、身份模型和 API 能力可能变化。执行具体任务时，应先读取当前安装版本的相关 Skill 或查询现行 schema，不要把本仓库中的概念示例当作永久有效的 CLI 参数文档。
